# 0.2.0 — 从采样到全量

0.1.1 的 G / ∩ / N 对照是「GitHub 前 300 × npm 242」的采样，越看越像抽样统计；这一版把两边都拉到接口上限（GitHub 最多 1000 条、npm 2500 条），按 `owner/repo` 归一后一屏并列，每行标清 `G` / `G∩N` / `N`。

## 新增

- **全量对照**：GitHub 按 stars 与 updated 各翻 10 页（搜索接口单查询上限 1000 条），npm 翻 10 页拿满 2500 条；结果落盘 `DSH_HOME/cache/daily-push-all.json`，6 小时内打开是 0 请求。
- **一屏三列 + 角标**：`∩` 视图 = 只在 GitHub / 两边都有 / 只在 npm，每行名称后带 `G` / `G∩N` / `N`。冲突时元数据取 GitHub、包名与安装命令取 npm。
- **每列独立翻页**：默认 15 条，「再加载 15 条（还剩 N）」，到底显示「没有更多了」；翻页只改显示条数，不复制行。
- **⚙ 里填 GitHub 令牌**：粘贴即校验（`/rate_limit`，不计额度），存 `DSH_HOME/daily-push-token.json`（600），前端只显示「已配置 · 尾号 xxxx」；带「测试」「清除」与实时剩余额度；也认 `GITHUB_TOKEN` / `DSH_GITHUB_TOKEN` / `GH_TOKEN`，文件优先。
- **数据截止时间**：头部与页脚都显示「数据截至 MM-DD HH:mm · N 小时前」，任何视图可见。
- **降级分列**：GitHub 限流或挂掉时只有 G 侧两列报错，npm 列照常显示。
- **搜索吃全量**：先在本地三千多条里筛（0 请求、即时），再让 GitHub 全站补漏；`∩` 屏里搜索就地筛三列、不切屏。
- **下载量单端点**：全量 npm 的下载量走 `/api/daily-consult.all.dl`，128 个一批，不重复传整份列表。

## 升级需知

- `∩` 视图**首次打开变慢**（10–30 秒，GitHub 搜索只能串行且页间要留间隔），之后走 6 小时磁盘缓存。
- 未登录 GitHub 时仍是 7 页约 660 条（搜索接口未登录限 10 次/分）；要抓满 1000 条就填令牌，任何 scope 都不需要。
- 无破坏性变更：配置、localStorage 键、安装命令都没动。

## 已知限制

- GitHub 搜索接口每个查询最多返回 1000 条，而 `topic:dsh-plugin` 实际约 3.2 万个仓库——「全量」指接口允许的全量。
- npm 搜索接口上限 2500 条（第 11 页起为空）。

## 安装

```bash
dsh plugin add dsh-daily-push
```
